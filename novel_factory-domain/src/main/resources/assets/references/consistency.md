# 连贯性保证机制

为确保长时间创作的故事连贯性：

## 写前必读

每次开始写新章节前：
1. 阅读当前章节计划与 `memory/summaries.json` 中的已完成章节摘要
2. 读取 `chapters/chapter-XXXX.txt` 的上一章正文结尾，了解当前悬念
3. 检查角色、物品、势力账本中的位置、状态、关系和持有物

## 穿针引线

在新章节中：
- 呼应前文埋下的伏笔和线索
- 提及之前发生的事件（自然融入）
- 让人物行为与之前保持一致

## 人物状态跟踪

注意人物在各章节中的变化和成长：
- 位置变化（人在哪里）
- 情绪状态（当前心情）
- 关系变化（与其他角色关系）
- 能力变化（获得新技能/信息）

## 悬念线延续

确保主线悬念逐步推进：
- 每章至少回应一个旧悬念
- 提出新悬念或升级现有悬念
- 不要遗忘任何未解的悬念

## 一致性检查清单

- [ ] 人物行为符合其性格设定
- [ ] 前后伏笔有呼应，逻辑闭环
- [ ] 高潮低谷分布合理，节奏恰当
- [ ] 时间线连贯（没有时间跳跃错误）
- [ ] 场景转换自然（没有凭空出现）

## 金手指/系统存在感一致性

仅当故事设定中明确存在金手指或系统（如剑意提取、签到、面板、读心等）时，才启用本节规则。没有金手指的故事必须跳过本节，不得为了满足检查要求凭空添加相关设定。

### 金手指一致性检查

- **使用频率（条件启用）**：仅对已确认存在金手指的故事生效；每 3 章至少有 1 次金手指的使用或有意义提及。如果连续 3 章没有出现，检查是否遗忘了设定，或是否明确交代了暂时不可用的原因。
- **能力边界一致**：金手指的能力边界一旦披露，后续不得违反。关键翻盘只允许用已披露的金手指能力，禁止临场加新技能。
- **使用成本一致**：每次动用金手指必须有明确的代价或限制（灵力消耗、虚弱期、暴露风险、冷却时间），不能无限免费使用。
- **成长曲线一致**：金手指的升级/解锁必须与主角的境界突破、关键剧情节点绑定，不能突然解锁新能力。
- **运作机制描述频率**：金手指/核心能力的运作机制（如"阵纹在眼中变成拓扑图""擦拭断剑提取剑意""系统面板显示数据"）在首次建立后，不得在后续章节重复大段描述。**同一机制的描述全篇至多2次**（首次建立时让读者理解运作方式、关键升级时展示能力变化），其余章节直接用行动展示操作过程和结果，不再解释原理。如果需要提醒读者机制存在，用角色的一个习惯性动作或一句话带出（如"他又闭上眼，阵纹在视网膜上铺展开来"——一句话带过，不展开描述）。

### 系统流小说的特殊要求

- **系统弹窗频率**：同一场景内系统弹窗不超过 2 次；连续章节不得每章都以系统框开场或收尾。
- **日常状态播报删除**：纯重复的状态播报（如"好感度+1""经验+10""任务完成"）直接删除，只在关键节点显示具体数字。
- **系统提示不得替代角色心理**：系统框只能给出客观信息（任务、数值、警告），角色的情绪、判断、决策必须由角色自己的内心或行动呈现，不能让系统旁白替角色总结感受。
- **系统升级/故障节点**：系统界面变化（升级、故障、乱码、消失）是重大叙事节点，必须有足够的铺垫和后续影响，不能轻描淡写一笔带过。

### 金手指遗忘的识别

如果出现以下情况，说明金手指被遗忘了，需要修改：
- 主角遇到困难时，明明可以用已建立的金手指解决，却完全没有想到使用
- 连续多章没有提及金手指，也没有解释为什么暂时不能使用
- 金手指的能力在后续章节中突然变强或变弱，没有任何铺垫
- 系统流小说中，系统突然消失，没有任何剧情解释

## 跨章段落重复检测（AI生成长篇重灾区）

AI生成时因上下文窗口限制，容易出现"记忆重复"——前文刚写过的场景，后文又原样重写一遍。这是长篇小说评审必须检查的项目。

### 检测方法

1. **相邻章节对比**：每写新章节前，必须阅读上一章最后30%的内容，确保新章节开头不重复上一章结尾的场景
2. **首尾段落对比**：重点检查第N章最后30%与第N+1章前30%是否有200字以上的重叠
3. **同一事件多章描写**：同一战斗/事件在不同章节中被重复描写时，必须有不同的视角、信息或后续发展，不能仅换喻体
4. **金手指机制重复描述检测**：检查核心设定/金手指的运作机制是否在多章中被重复大段描述。同一机制的描述全篇至多2次（首次建立+关键升级），其余章节应通过角色的具体操作和结果呈现，不得每章用旁白重新解释运作原理。检测时搜索核心机制的关键词（如"拓扑图""剑意提取""系统面板"），统计出现次数和每次的描述篇幅。

### 重复处理

- **完全重复**：直接删除重复段落，用过渡句衔接（时间/空间/视角的推进）
- **同一事件不同视角**：保留信息密度更高的版本，另一版本补充新信息（角色反应、环境变化、后续发展）
- **金手指机制重复**：保留首次建立和关键升级时的描述，其余章节的大段机制描述删除，替换为角色的具体操作动作和能力效果（一句话带过机制存在，不展开解释原理）
- **预防原则**：每章开头不得重复上一章结尾的场景描写，必须有时间/空间/视角的推进

### 典型案例（模式示例，非本书事实）

> 以下只描述这类问题的**形态**，章号与人名均为占位符。它们与本作当前进度无关，
> **不得当作本故事已发生的剧情引用**，也不要据此推断任何角色或地点的存在。

- **整段复刻**：第 N 章后半与第 N+1 章前半，都写"主角推开殿门，看见殿中央的青铜鼎"，约 500 字几乎逐句相同
- **同事件换喻体重写**：第 M 章与第 M+1 章各写一次"主动迎击怪物洪流"，只把"如潮水般涌来"换成"如黑云般压境"
- **重复战斗**：同一对手的同一招式在第 K 章与第 K+1 章各完整描写一遍，只换了人名与兵器名

## 全书一致性台账（长篇小说必建）

长篇小说创作必须建立并维护以下台账，每章写作前核对，每章完成后更新：

### 角色状态台账

| 项目 | 跟踪内容 |
|------|----------|
| 位置 | 当前所在地点，与上一章的空间关系 |
| 伤势 | 所有未愈合伤口的位置、严重程度、恢复进度 |
| 装备 | 持有的武器、防具、法宝、物品及其状态 |
| 境界/能力 | 修为等级、已掌握的技能/剑意/法术 |
| 人际关系 | 与其他角色的关系状态（盟友/敌人/暧昧/决裂） |
| 情绪状态 | 当前的主导情绪和心理状态 |

### 世界观设定台账

| 项目 | 跟踪内容 |
|------|----------|
| 力量体系 | 境界划分、升级条件、能力边界 |
| 地理 | 地点位置、距离、旅行时间、环境特征 |
| 历史 | 已揭示的历史事件、时间线、传说 |
| 规则 | 世界运行规则、法术原理、限制条件 |
| 势力 | 各组织/门派/势力的立场、实力、关系 |

### 关键物品台账

| 项目 | 跟踪内容 |
|------|----------|
| 持有者 | 当前持有该物品的角色 |
| 状态 | 物品的完好程度、能量状态、特殊效果 |
| 位置 | 物品所在的具体位置 |
| 历史 | 物品的来源、经过的持有者、关键事件 |

### 时间线台账

- 每章发生的具体时间点（相对故事开始的时间）
- 与前后章的时间间隔
- 关键事件的时间顺序
- 季节/天气变化的合理性

## 伤情跟踪机制（战斗型小说必建）

战斗型小说中，伤口的处理最容易出现前后矛盾。必须建立伤情台账：

### 伤情记录要素

- **受伤时间**：哪一章、哪个事件中受的伤
- **受伤位置**：具体的身体部位
- **严重程度**：轻伤/中度/重伤/致命
- **治疗情况**：是否接受治疗、治疗方式、恢复进度
- **对行动的影响**：该伤口如何影响角色的战斗和日常行动

### 伤情处理原则

1. **同一伤口疼痛描写全篇至多2次**：第一次在受伤时（展示严重程度），第二次在关键节点（展示角色带伤作战的意志），其余用行动受限暗示
2. **带伤作战必须有实际代价**：动作变形、力量下降、被对手针对，不能"喊疼但不影响输出"
3. **恢复必须有过程**：重伤不能"下一章就好了"，必须有治疗、休养、逐步恢复的过程
4. **旧伤可能复发**：关键战斗中旧伤可能复发，增加紧张感和真实感

## 标题唯一性管理

长篇小说中章节标题容易出现重复或模板化，必须管理：

### 标题检查清单

- [ ] 全书所有章节标题唯一，无重复
- [ ] 标题与本章核心内容匹配
- [ ] 避免模板化标题（"XX的危机""新的开始""风暴前夕"反复出现）
- [ ] 标题有具体的意象或事件指向，非空泛概括
- [ ] 标题不直接剧透本章结局

### 标题重复检测方法

写完一定数量章节后，提取所有章节标题列表，检查：
1. 是否有完全相同的标题
2. 是否有高度相似的标题（仅换1-2个字）
3. 是否有模板化标题的批量使用

## 尾声/收尾管理

长篇小说的高潮过后，尾声部分容易拖沓或仓促：

### 尾声篇幅控制

- 尾声不超过总篇幅的5-8%，以3-5章为宜
- 只交代主要角色的结局和关键伏笔的回收
- 不引入新角色、新设定、新冲突

### 结局节奏

- 主要角色的结局应在最后2-3章内逐步交代
- 不要全部堆在最后一章（仓促），也不要用10章写日常（拖沓）
- 用具体的场景和动作结尾，不用抽象的说教和升华
- 留下情感余韵，让读者有回味空间
