# 范例蒸馏方法论

如何从成品文本（你自己满意的章节、或公开值得借鉴的作品）中提炼可复用的结构资产，沉淀成 exemplar-* 范例与检索资产。核心原则一句话：**蒸馏的是结构，不是腔调；是机制，不是原句。**

## 一、先决定值不值得进库

不是所有文本都值得蒸馏。优先收这些：

- 开头有明显抓手，前 300~500 字就能看出异常局面
- 卖点和冲突绑得紧，不是纯设定介绍
- 某个局部特别强：开头、主角亮相、高张力对白、章末余韵
- 能补足当前语料缺口（某类题材太少、某种关系流不够）

不建议收这些：

- 设定很大但前几章不起事
- 情绪很多但事件很弱
- 语言表面花哨但结构价值低
- 和现有样本高度重复，不能带来新的结构信息

判断核心：**不是"这篇文好不好看"，而是"它有没有可迁移的结构价值"。**

## 二、蒸馏保留什么

重点保留：

- 核心卖点
- 冲突起势方式（一个危机怎么被推到读者面前）
- 主角出场方式
- 信息投放方式（先给什么、藏什么）
- 对白如何带身份差和后果
- 章末停在哪个变化点上（悬念/未决/情绪拉扯）

不要保留：

- 某一句漂亮文案
- 某个作者习惯用的口头禅
- 过强的表面修辞
- 能直接识别来源的句式复制

## 三、四类固定结构摘录

固定抽四类，不做文学分类，只做"写作最常复用的结构部件"：

| 摘录类型 | 抓取标准 | 不达标的样本 |
|---------|---------|-------------|
| 开头钩子 | 前 300~500 字的异常局面/人物处境 | 环境渲染或设定介绍铺了半天 |
| 主角亮相 | 第一次让读者记住这个人的动作/选择/对白 | 用"他拥有XX的品质"式直接定性 |
| 高张力对白 | 对话里有真实冲突、后果或潜台词，能带身份差 | 随便抓到的一句话、寒暄 |
| 结尾余韵 | 停在变化/悬念/情绪拉扯上，读者想知道下一步 | 事件平息后的收束废话 |

## 四、提炼成范例文件的写法

参照 exemplar-* 范例格式：每条范例 = 【场景指令】+【正文片段】+【拆解要点】。

- **场景指令**：一句话描述场景（"被逼问核心事实，主角隐忍·部分真相释放"），方便索引与检索
- **正文片段**：从原文本裁剪，保留结构完整的片段，不是摘金句
- **拆解要点**：写清楚"这段为什么成立"——信息差在哪里、动作如何替代情绪、对白如何藏动机。拆解是范例的灵魂，没有拆解的范例等于复制粘贴

## 五、蒸馏流程

原文 → 清洗（去平台格式/去水印）→ 摘要 → 打题材标签 → 抽四类结构摘录 → 写拆解 → 入池。

维护原则：

- **优先改规则，不要为单篇特例硬编码**——某类样本总是蒸馏不好，先回头修摘录标准
- **优先改规则，不要硬塞脏数据**——标签总打错时补关键词表，而不是手工逐条改
- **蒸馏不是"训练模型记忆"**——不把全文塞进 prompt，只沉淀可迁移的结构信息
- **警惕"作者句子好看"≠"适合蒸馏"**——漂亮文案不能当结构资产用

## 六、什么时候该补新样本

1. 模型在某类题材上总给出很泛的答案 → 本地范本不够
2. 某种需求经常出现，但现有标签检索不到合适案例
3. 某个类型的开头/对白/章末明显不够强
4. 新平台、新题材、新关系模式已形成稳定套路，但语料库没覆盖

补样本时不要只追数量：**更全的题材覆盖 + 更清晰的结构标签，比单纯多几十篇相似文本更有用。**

## 七、反查原文

检索到摘录后，不要停在一句话层面。回查上下文（exemplar 范例应保留来源章节线索），看它前面怎么铺、后面怎么收——摘录是路标，全文才是完整的路。
