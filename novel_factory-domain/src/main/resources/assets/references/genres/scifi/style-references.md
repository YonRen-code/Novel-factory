# 科技流/黑科技 风格参考

科技流的质感来自"技术自洽 + 研发有成本 + 商业有账目"。本文件随题材包注入正文场景。核心方法论：**左右互搏**——每个技术设想先试图证伪它，修补到驳不倒再写进正文。

## 技术设定的自洽

- 技术树动笔前定稿（哪些技术存在、先后依赖、各自的边界），落笔后禁止临时长出新枝救场
- 每项技术写清三件事：**能做什么、不能做什么、代价是什么**——边界比能力重要，读者靠边界判断紧张感
- 现实技术为锚：虚构技术挂在真实技术的延长线上（现有工艺 + 一步跨越），跨越幅度一次只走一步
- 技术原理**一段讲完**：机理、关键参数、失败风险各一两句，其余用结果与场面呈现——大段原理讲解既拖节奏又触发机制重复检查
- 偶然性来自人物（失误、私心、政治），必然性来自技术（该来的突破总会来）——两者的因果不要混用

## 研发与成本

- 研发必须烧真资源：资金缺口、设备排队、实验失败、人才流失，每卷至少正面写两次失败
- 时间尺度诚实：一项技术从立项到落地至少跨十几章，禁止三章磨一剑
- 测试与验证环节不可跳过：样机、试产、事故召回至少各出现一次，出过事故的技术才有可信度
- 数据要具体但不堆砌：关键参数给三五个（良率、成本、时长），其余用对比（"比现有方案快一半"）

## 商业与账目

- 融资、股权、定价写清结构：让出多少股份、估值多少、谁进董事会——科技公司死于股权多于死于技术
- 收入要可核算：客单价 × 客户数 × 复购，大订单写清客户是谁、用来干什么
- 竞争写生态不写单点：对手拼的是专利池、供应链、标准话语权，不只是"也搞出了黑科技"
- 卡脖子的环节提前埋（材料、设备、专利授权），被断供时读者能想起伏笔

## 人物与术语

- 科学家有师承与学派：导师的一句话、学术会议上的交锋，胜过十页技术描写
- 外行视角当翻译器：用投资人、记者、家人的提问带出技术解释，禁止主角自问自答式科普
- 术语首次出现给一句白话注脚，此后直接用——既专业又不设门槛
- 技术命名要像真的（代号 + 型号 + 版本号），禁止"超级芯片一号"式命名
